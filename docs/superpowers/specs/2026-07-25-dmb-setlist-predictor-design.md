# DMB Setlist Predictor — Design

Date: 2026-07-25 (built autonomously; user asked to continue until a working
site predicts tonight's Hartford, CT show)

## Goal

A simple website that predicts the Dave Matthews Band setlist for the next
show (tonight: The Meadows Music Theatre, Hartford, CT, 2026-07-25). Looks
don't matter; the algorithm does.

## Data source

setlist.fm (community setlists, curl-accessible). antsmarching.org and
dmbalmanac.com sit behind a Cloudflare browser challenge, so setlist.fm is the
scriptable source. Scrape all shows from 2024-01-01 forward: the current 2026
summer tour drives the prediction; 2024–2025 supply priors (encore behavior,
song positions, repeat-gap behavior).

## Components

1. `scraper.py` — crawls setlist.fm artist index pages + each show page into
   `data/shows.json` (date, venue, city, ordered songs, encore boundary).
   Disk cache + 1.2 s rate limit.
2. `predict.py` — the algorithm (below); writes `data/prediction.json`.
3. `build_site.py` — renders `site/index.html` from the prediction: ordered
   predicted setlist with confidence, bubble songs, methodology, data stats.
4. Served with `python3 -m http.server` from `site/`.

## Algorithm

Empirical, tour-centric scoring — parameters estimated from the data, not
hardcoded:

- **Tour pool & frequency**: P(song in show) = plays this tour / shows this
  tour, lightly smoothed with prior-year frequency for songs with few 2026
  plays.
- **Rotation / gap model**: estimate from history P(played tonight | last
  played k shows ago) for k = 1 (back-to-back), 2, 3+. DMB's known
  no-back-to-back tendency falls out of the k=1 estimate rather than being
  assumed. Score = tour frequency x gap multiplier (k multiplier / base rate).
- **Slot model**: separate empirical distributions for opener, main-set
  closer, and encore membership (this tour, backfilled by prior year).
  Position-in-set percentile per song orders the middle of the set.
- **Set length**: median main-set length and median encore length this tour.
- **Assembly**: opener = top scorer among opener-pool songs; encore drawn
  from encore-pool scores; closer from closer pool; remaining main-set slots
  filled by overall score; middle ordered by average position percentile.
  A song appears at most once.

Output includes per-song confidence (normalized score → calibrated to the
song's played-tonight probability) and the next 10 "bubble" songs.

## Trade-offs considered

- setlist.fm API (needs key, user absent — rejected) vs HTML scraping
  (works now — chosen).
- ML model (logistic regression per song) vs empirical heuristic scoring:
  with ~40 tour shows the heuristic with empirically estimated gap/slot
  parameters is as strong and fully explainable — chosen.
- Dynamic web app vs static generated page: static page regenerated by
  `predict.py` is simpler and sufficient — chosen.

## Testing

- Backtest: hold out each of the last 5 shows of the tour, predict it from
  prior shows only, report hit rate (predicted ∩ actual / actual). Target:
  beat naive "most frequent N songs" baseline.
- Site verified by loading it locally.
